## 一、這是什麼

使用者（hannibal8856）陸續請 Claude 把家裡的桌遊和網路上的規則，做成「手機可玩、單一 HTML 檔」的網頁遊戲。

- 多數可以和電腦對戰，也有幾款支援多人用同一支手機輪流玩。

  - `games`：工作分支，和 master 相同。

## 三、怎麼修改或新增遊戲

### 1. 兩種版本
- **Artifact 版**：沒有 `<!doctype>`、`<html>`、`<head>`，發布時由平台包上。
- **網站版**：Artifact 版外面再包一層外殼：

```html
<!doctype html><html lang="zh-Hant"><meta charset="utf-8"><meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover"><style>:root{padding-top:env(safe-area-inset-top,0px);padding-bottom:env(safe-area-inset-bottom,0px)}body{margin:0;font-size:14px}[hidden]{display:none!important}img{max-width:100%}</style>
（Artifact 版內容）
</html>
```

- 修改方式一：直接改網站版。第一行之後、最後的 `</html>` 之前就是遊戲本體；改完再發布回 Artifact。
- 修改方式二：用 Artifact 工具 `action: "read"` 讀回 Artifact 版，改好後重新包殼放進倉庫。

### 2. 新增遊戲
1. 做好單一 HTML 檔，包上外殼，存成 `英文名.html`。
2. 在 `index.html` 對應的區塊加一張 `<a class="game" href="檔名">` 卡片，圖示底色在 `<style>` 裡加一個 class。「整理」功能會自動處理新卡片，不用改程式。
3. Git：
   - 在 `games` 分支 commit，commit 訊息結尾加上系統提供的 `Co-Authored-By` 與 `Claude-Session` 兩行。
   - 使用者同意後，fast-forward 合併到 `master` 並推送。使用者說「放到網站上」就算同意。
   - 推送前先 `git fetch origin master`，因為使用者可能從別的地方推過檔案（例如 `bus.html`）。

## 四、遊戲廳首頁的「整理」功能（2026-10-31 加入）

- 右上角「整理」→ 點遊戲卡片切換「顯示中／已隱藏」→ 按「完成」。
- 隱藏的遊戲不會出現在列表；整區都隱藏時，連區塊標題也會藏起來。
- 有隱藏遊戲時，標題下方會提示「已隱藏 N 款遊戲，按右上角「整理」可以叫回來」。
- 設定存在瀏覽器的 `localStorage`（key：`hall-hidden`，內容是隱藏遊戲的 href 陣列）。
  - **只記在那支手機的那個瀏覽器上**，別人打開網站還是看得到全部遊戲。
  - 如果使用者想讓所有人都看不到某款遊戲，要直接從 `index.html` 拿掉那張卡片（遊戲檔案可以保留）。

## 五、線上多人（礦坑淘金、圓桌騎士、蟲蟲吹牛、藥鍋郎中）

### 使用方式
1. 遊戲開頭選「這支手機／線上開房／加入房間」。
2. 房主建立 4 碼房號，可以按「分享邀請連結」，連結格式是 `檔名.html?room=房號`。
3. 朋友輸入房號加入。
4. 房主在大廳設定人數等選項，空位由電腦補。
5. 每款都有聊天和 12 個表情；表情會在所有人畫面上方跳出泡泡。

### 架構（四款共用，程式碼幾乎一樣）
- **連線**：PeerJS（WebRTC）1.5.4 版，從 cdn.jsdelivr.net 載入，失敗再試 unpkg。用 PeerJS 的免費公用伺服器配對，不需要自己的伺服器或帳號。
- 房主的 Peer ID 是 `hannibal-{mine|avalon|roach|quacks}-房號`。
- **房主的瀏覽器跑整個遊戲引擎**：
  - 輪到遠端玩家時，`ask()` 把提示存進 `S.rprompts[座位]`，等對方回傳 `{t:'ans', pid, v}`。
  - 房主用 `validAns()` 檢查回覆；不合法就換新的 pid 重送。
- **同步畫面**：每次 `render()` 後，`syncSoon()` 把 `viewFor(座位)` 傳給每位玩家。玩家端用 `applyView()` 重建一個 `S`，沿用同一套畫面程式；玩家端的 `answer()` 改成把答案傳給房主。
- **大家一起看的畫面**（回合結算、投票結果等）：用 `S.shared` 讓每人自己看、自己關，房主按繼續就往下走。
- **斷線**：
  - 房主每 3 秒 ping，12 秒沒回應就判定離線，由電腦代打（`botAnswer()`）。
  - 用同一個名字重新加入，會接回座位。
  - 房主離開則整局結束。

### 各款的差異
- **礦坑淘金**：
  - 只傳自己的手牌、身分、藏寶圖結果；別人的手牌只有張數，未翻開的目標卡不含金礦資訊。
  - 回合結算時才公開全部身分。
  - 一代、合併版都能選。
- **圓桌騎士**：
  - 投票和出任務是所有人同時進行（`Promise.all`），座位會顯示「思考中…／已投票／已交牌」。
  - 夜晚資訊由房主算好（`nightInfo(座位)`）。
  - 刺殺階段才看得到邪惡方身分，遊戲結束才全部公開。
  - 角色清單用排序後的版本傳，避免從順序推出誰是誰。
- **蟲蟲吹牛**：只傳自己的手牌；傳遞中的牌不含牌面，只有選「偷看並轉傳」的人會收到牌面。
- **藥鍋郎中**：
  - 製藥時所有真人同時抽（`Promise.all` 跑每個人的 `brewHuman`），計分和購買照起始玩家順序。
  - 這款沒有需要保密的資訊，傳整個狀態（扣掉占卜牌堆）。
  - 大廳可選人數 2～4、藥典第 1～4 組、大釜面。

### 測試方式
- 在本機用 npm 的 `peer` 套件跑 PeerServer：`peerjs --port 9000 --host 127.0.0.1`。要加 `--host 127.0.0.1`，這個環境不支援 IPv6。
- 網址加 `?peerhost=127.0.0.1:9000`，就會改連本機伺服器。
- 用 Playwright 開 3 個瀏覽器 context（各自獨立）當 3 位真人，把 peerjs.min.js 的網址 route 到本機檔案（`npm pack peerjs@1.5.4` 取得）。
- 網頁要用 http 伺服器、而且用網站版（有 `<meta charset>`）測，不然中文會亂碼。
- 四款都測過完整對局、中途斷線再加入，都沒有錯誤。
- **限制**：
  - 沒辦法在這裡用真的公用伺服器測。使用者第一次和朋友連線時，請他回報有沒有成功。
  - 極少數公司或學校網路會擋 WebRTC。
  - Claude Artifact 版可能因頁面安全限制無法連線，線上多人請用網站版。

## 七、共同的程式架構

- 全部是單一 HTML 檔，只用 Google Fonts；線上多人的 4 款另外從 CDN 載入 PeerJS。
- 遊戲流程：
  - `ask(prompt)` 回傳 Promise，玩家操作時呼叫 `answer(value)` 解開，所以流程可以用 `async/await` 寫成一條直線。
  - 電腦玩家用 `nap(ms)` 暫停；重新開局時用 `gid` 判斷，丟出 `'stop'` 中止舊流程。
- 畫面：`render()` 依目前狀態整頁重畫；彈出視窗用 `renderSheet()`，依 `prompt.type` 決定開哪一個。
- 測試入口：多數檔案有 `window.__xxx`，例如 `__q`／`__qBots`／`__qSpeed`（藥鍋郎中）、`__roach`、`__av`、`__mine`、`__civ`。線上版另有 `__xxxNet`。
- CSS 注意：有自訂 `display` 的元素會蓋過 `hidden` 屬性，每個檔案都要有 `[hidden]{display:none!important}`。

### 測試方式
- 用預裝的 Playwright：`require('playwright')`。不要重新安裝。
- 把等待時間調到很短，用腳本自動點擊、跑完整局；檢查有沒有 `pageerror`，並截 390px 寬的手機畫面。
- 平衡檢查：讓電腦玩所有座位，跑幾十局統計勝率和分數。
- 結束測試時關掉本機伺服器，用 `pkill -f "peerjs --port 900[0]"` 這種寫法，避免 pkill 把自己的 shell 也殺掉。

## 八、環境限制

- 這個雲端環境的網路政策擋掉大部分網站，包括 fantasyflightgames、pixnet、boardgamegeek、andyventure、各商店頁和 github.io。可以用搜尋，但只拿得到摘要。npm registry 可以用。
- 需要讀某個網頁時，請使用者貼上文字、拍照或上傳 PDF。
- 連不上 github.io，所以推到 master 之後無法從這裡確認網站是否已更新。GitHub Pages 通常 1～2 分鐘內會更新。
- 使用者拍的卡片如果有保護套反光，可以先用 PIL 裁切放大、提高對比；還看不清楚就請使用者拿出保護套重拍。

2. **藥鍋郎中**：如果使用者從正上方拍計分板，可以把老鼠尾巴位置改成完全正確。
3. **文明崛起**：如果使用者提供官方規則書，就把自製的數值和卡牌換成正式內容。
4. **市長大建設**、**從種子到杯子**：使用者拍實體卡片後，換成真的卡片內容。
5. **礦坑淘金**：使用者數了實體二代卡片後，修正水晶數量和行動卡張數。
6. **異形巢穴**：有正式規則書（含數值）的話，照正式數值重做。
7. 早期的三款（UNO、UNO Flip、2048）頁面文字是簡體，其他都是繁體，可以考慮統一。
